# CoverScore Assessment Catalogue™

**Version:** v1.0 | **Status:** Canonical | **Owner:** CoverScore Product & Intelligence team

---

## 1. Purpose

The Assessment Catalogue is the register of every CoverScore assessment product. It defines the product identifier, category, pillar set, assessment structure, and lifecycle status of each product. Nothing is assessed unless it is in this catalogue.

## 3. Assessment Standards

Every assessment product must:

1. Have a **unique product ID** from this catalogue.
2. Define its **pillar set** (5–9 pillars) before launch.
3. Produce a **CoverScore 0–100** with the standard bands.
4. Produce the **full intelligence output set** (see Intelligence Standards).
5. Capture **confidence** and **evidence** per answer and per pillar.
6. Be **versioned** (e.g., SCH v2.1).
7. Have a documented **assessment flow** (question order, branching, optional modules).

---

## 4. Assessment Structure

| Component | Requirement |
|-----------|-------------|
| Introduction | Plain-language purpose, time estimate |
| Core questions | One per pillar + confidence capture |
| Branching | Follow-up depth based on answers |
| Optional modules | Product-specific deep dives |
| Output | CoverScore, pillars, intelligence objects |
| Advisor Brief | Auto-generated (12 mandatory sections) |
| Report | Auto-generated (13 sections) |

---

## 5. Version Control

- Every product has a version number: `MAJOR.MINOR` (e.g., `SCH v2.1`).
- **Major** — pillar set, scoring model, or output structure changes.
- **Minor** — question wording, branching, or presentation refinements.
- Version history is recorded with date, author, and change summary.

| Deprecated | Being phased out; new assessments not issued |

## 8. Catalogue Governance

- New products require a catalogue entry before any assessment is issued.
- Changes to a pillar set or scoring model are **major** version changes.
- The catalogue is the reference for all product names, IDs, and pillar sets in training, prompts, and operations.
